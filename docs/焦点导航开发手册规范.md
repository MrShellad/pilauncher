# 焦点导航开发手册规范

## 1. 目的与适用范围

本规范约束 PiLauncher 中的键盘、手柄、Steam Deck 社区键位布局和鼠标共用的焦点导航行为。适用于所有可通过方向键、D-Pad、摇杆或模拟键盘操作的页面、弹窗、侧栏、列表和浮层。

目标：

- 焦点始终可见、可预测、可恢复。
- 任何可操作区域都不能因动态布局、筛选、动画或状态变更而陷入死路。
- 键盘和手柄的导航结果保持一致。
- 弹窗不会把焦点泄漏到后台；关闭后不会丢失原页面焦点。

本文中的“方向输入”指键盘方向键、手柄 D-Pad、摇杆，以及 Steam Deck 社区布局模拟出的 `W/A/S/D` 或方向键。

## 2. 当前架构

| 层级 | 模块 | 职责 |
|---|---|---|
| 输入适配 | `src/ui/focus/InputDriver.ts` | 将键盘、手柄和 Steam Deck 模拟输入转换为统一 Action，并为手柄派发方向键事件。 |
| 焦点运行时 | `@noriginmedia/norigin-spatial-navigation` | 注册可聚焦节点，处理几何空间导航、焦点边界和焦点切换。 |
| 焦点上下文 | `src/ui/focus/FocusProvider.tsx` | 初始化运行时，维护鼠标、键盘、手柄模式，合并用户键位。 |
| 焦点边界 | `src/ui/focus/FocusBoundary.tsx` | 限制弹窗/面板中的焦点范围，并在边界节点被误聚焦时恢复子节点焦点。 |
| 可聚焦原语 | `src/ui/focus/FocusItem.tsx` | 为原生元素注册 `focusKey`、Enter 和方向输入。 |
| UI 原语 | `OreButton`、`OreSwitch`、`OreIconButton` | 将视觉控件接入 `FocusItem`。 |

业务组件不得绕过上述机制自行维护 `document.activeElement` 或手写全局键盘监听。需要非标准导航时，应通过 `onArrowPress` 和 `setFocus` 完成。

## 3. 不可违反的规则

1. 每个可操作组件必须有稳定、唯一的 `focusKey`。
2. 动态列表的 `focusKey` 必须基于实体 ID，不能基于数组下标。
3. 弹窗、抽屉、浮层打开后必须设置初始焦点；关闭后必须恢复到可用的来源焦点或安全降级焦点。
4. 使用 `FocusBoundary` 的区域必须同时提供 Escape/Cancel 退出路径。
5. 任何可能只剩一个按钮的动态区域，必须提供离开该按钮的方向导航或明确的 Cancel 路径。
6. 当视觉布局会因状态、动画、分组、排序、展开/折叠而变化时，不能只依赖空间几何算法，必须提供显式焦点序列。
7. 焦点不能指向未挂载、禁用、隐藏、透明但仍在 DOM 中，或已经失效的节点。
8. 按钮、开关、图标按钮必须使用已有 OreUI 原语；不要直接包裹未经焦点注册的 `button` 或 `div`。

## 4. Focus Key 命名规范

### 4.1 格式

使用 `功能-区域-动作-实体ID` 的小写 kebab-case 格式。实体 ID 必须经过编码，避免路径分隔符或空格造成冲突。

```ts
// 固定控制
'btn-taskpanel-hide'
'btn-taskpanel-clear-completed'

// 动态任务控制
`btn-log-${task.id}`
`btn-pause-${task.id}`
`btn-cancel-${task.id}`
`btn-retry-${task.id}`
```

### 4.2 禁止写法

```ts
// 排序、筛选或分页后会漂移
`download-action-${index}`

// 多处复用时会冲突
'confirm'

// 由展示文本组成，国际化后不稳定
`btn-${task.title}`
```

### 4.3 生命周期

- 元素显示期间，`focusKey` 不得变化。
- 实体状态变化但实体未替换时，继续复用同一 `focusKey`。
- 当前焦点元素将被删除时，删除前或删除后下一帧必须调用 `setFocus` 转移到同一区域的后继节点、前驱节点或退出按钮。

## 5. 何时使用空间导航，何时使用显式序列

### 5.1 可以依赖空间导航的场景

以下场景可以仅依赖 Norigin 的几何计算：

- 静态网格，例如实例卡片、固定工具栏。
- 同一行或同一列、尺寸一致、相邻关系稳定的按钮组。
- 元素不会因进度、日志、错误状态或动画而改变位置。

即使是这些场景，也必须有稳定 `focusKey` 和可见的 focused 样式。

### 5.2 必须使用显式序列的场景

以下任一条件成立时，必须使用 `onArrowPress` + `setFocus`：

- 列表项会按时间、进度、状态重新排序。
- 每行操作按钮数量因状态而变化。
- 展开/折叠会插入或移除内容。
- 操作按钮被放在左右两端、跨分组、跨滚动容器或跨动画节点。
- 某类实体只剩一个可操作按钮。
- 焦点区域处于 `FocusBoundary` 中，不能允许几何计算失败后向外泄漏。

下载任务管理器属于上述场景：任务会按状态分组并按 `lastUpdate` 排序，资源、实例、更新任务的操作集合不同。因此其操作区使用显式序列，而不是假设“查看日志”右侧一定存在可导航按钮。

## 6. 动态列表的标准实现

### 6.1 构建可见操作序列

序列必须由当前实际渲染的控制项生成，顺序与用户阅读/操作顺序一致，并排除禁用和折叠区域。

```tsx
const focusOrder = useMemo(() => [
  ...visibleTasks.flatMap((task) => {
    const keys = [`btn-log-${task.id}`];

    if (task.status === 'error') {
      if (task.retryTask || task.retryAction) keys.push(`btn-retry-${task.id}`);
      keys.push(`btn-complete-${task.id}`);
    } else if (task.status === 'downloading') {
      keys.push(`btn-cancel-${task.id}`);
    }

    return keys;
  }),
  'btn-panel-hide',
], [visibleTasks]);
```

### 6.2 处理方向输入

方向输入处理器必须：

1. 仅接管需要线性保证的方向。
2. 过滤当前不存在的节点。
3. 将焦点移动到后继/前驱节点。
4. 返回 `false` 阻止 Norigin 再进行一次不确定的几何导航。

```tsx
const handleArrowPress = useCallback((focusKey: string, direction: string) => {
  if (!['left', 'right', 'up', 'down'].includes(direction)) return true;

  const available = focusOrder.filter((key) => doesFocusableExist(key));
  const currentIndex = available.indexOf(focusKey);
  if (currentIndex < 0) return true;

  const delta = direction === 'left' || direction === 'up' ? -1 : 1;
  const nextIndex = Math.max(0, Math.min(available.length - 1, currentIndex + delta));
  const nextKey = available[nextIndex];

  if (nextKey && nextKey !== focusKey) setFocus(nextKey);
  return false;
}, [focusOrder]);
```

将该处理器传入序列中的每个原语：

```tsx
<OreIconButton
  focusKey={`btn-log-${task.id}`}
  onArrowPress={(direction) => handleArrowPress(`btn-log-${task.id}`, direction)}
  {...props}
/>
```

### 6.3 边界行为

- 在序列首项继续向上/左，保持当前焦点并返回 `false`。
- 在序列末项继续向下/右，保持当前焦点并返回 `false`。
- 如产品明确需要循环导航，必须在组件注释和测试中说明；默认不循环，防止用户误以为焦点丢失。
- 如果存在“关闭”“返回”“隐藏面板”等退出控制，必须放在序列末尾。

## 7. 弹窗、抽屉与焦点恢复

### 7.1 打开

- 打开前记录来源页面当前焦点。
- 面板动画完成后再调用 `setFocus`，避免节点尚未注册或布局仍为初始位置。
- 初始焦点优先选择首个可操作任务；没有任务时选择关闭/隐藏按钮。
- 不要把初始焦点固定为某个可能成为唯一控件的按钮，除非该区域有显式离开路径。

### 7.2 关闭

- 子抽屉关闭时，焦点返回打开它的触发按钮。
- 主面板关闭时，优先恢复来源焦点；来源已卸载时使用当前页安全焦点；最后降级到浮动入口。
- 删除当前聚焦任务时，先将焦点交给面板的稳定控制项，再删除任务，避免焦点指向已经卸载的 DOM。

### 7.3 焦点边界

`FocusBoundary` 用于模态面板和抽屉，禁止焦点跳到背景页面。边界不是导航策略本身：它只能限制范围，不能保证在范围内找到下一个节点。动态区域仍需显式导航序列。

## 8. 状态更新、排序和动画要求

1. 高频进度更新不得重建全部任务行。使用稳定的实体 ID 和 `React.memo`，确保只重绘变化任务。
2. 焦点顺序可随当前可见状态重算，但不能因无关任务的进度更新而丢失当前 `focusKey`。
3. 需要重新排序的列表中，焦点移动以“当前序列”而不是屏幕绝对位置为准。
4. 不要在正在聚焦的可操作节点外包裹会持续变换位置或尺寸的 `layout` 动画；必要时将动画移到非交互容器。
5. 展开/折叠后，如原焦点被隐藏，必须把焦点移到展开按钮或该组的首个可见操作。
6. `doesFocusableExist` 只能用于确认注册状态；业务逻辑仍须排除已知禁用项，不能把禁用节点加入显式序列。

## 9. 下载任务管理器专项约束

相关实现位于：

- `src/features/Download/components/DownloadManager/index.tsx`
- `src/features/Download/components/DownloadManager/TaskPanel.tsx`
- `src/features/Download/components/DownloadManager/TaskItem.tsx`
- `src/features/Download/components/DownloadManager/TaskLogDrawer.tsx`

### 9.1 操作顺序

每个可见任务按以下顺序加入焦点序列：

| 任务状态/类型 | 顺序 |
|---|---|
| 资源下载中 | 查看日志 -> 暂停/继续 -> 取消 |
| 实例下载中 | 查看日志 -> 取消 |
| 启动器更新中 | 查看日志 -> 下一个任务或面板底部控制 |
| 失败且可重试 | 查看日志 -> 重试 -> 清除失败任务 |
| 失败且不可重试 | 查看日志 -> 清除失败任务 |
| 已完成 | 查看日志 -> 实例配置/关闭任务 |
| 已折叠的完成组 | 不加入任务操作序列 |

任务操作之后依次为：完成组展开/收起（若存在）、自动弹窗开关、清除已完成任务（若可用）、隐藏面板。

### 9.2 日志抽屉

- 打开日志后，焦点进入关闭日志按钮。
- 关闭日志后，焦点返回对应的查看日志按钮。
- “跳至最新日志”出现时必须拥有独立 `focusKey`。
- 日志滚动区域不是焦点死路；Cancel/Escape 始终先关闭日志抽屉，再关闭任务面板。

## 10. 开发自检清单

提交前逐项确认：

- [ ] 所有新增可操作元素均使用 OreUI 原语或 `FocusItem`。
- [ ] 动态元素的 `focusKey` 基于稳定实体 ID。
- [ ] 打开、关闭、删除、筛选、折叠后焦点都有明确目标。
- [ ] 每个 `FocusBoundary` 有可用的 Cancel/Escape 行为。
- [ ] 动态列表已判断是否需要显式焦点序列。
- [ ] 状态变化后单个按钮不会成为无方向出口的死路。
- [ ] 键盘方向键与手柄 D-Pad/摇杆的导航路径一致。
- [ ] Steam Deck 键盘模拟布局下，`W/A/S/D` 和确认键可完成同一流程。
- [ ] 鼠标模式下不会错误显示手柄焦点样式，也不会破坏原生点击。

## 11. 手工回归用例

每次修改焦点相关代码，至少覆盖以下用例。

### 11.1 基础导航

1. 使用方向键打开目标面板。
2. 从初始焦点按四个方向，确认焦点始终可见且不会跳到背景。
3. 在序列首尾继续按方向，确认焦点不丢失、不泄漏。
4. 使用 Enter/确认键激活当前控制，确认行为与鼠标一致。
5. 使用 Escape/取消键关闭当前层，确认焦点返回预期触发点。

### 11.2 动态列表

1. 创建至少三个不同状态的列表项。
2. 在中间项聚焦时触发进度更新、排序更新和状态切换。
3. 验证焦点仍停在同一实体的同一控制，或按规则移动到安全后继。
4. 删除当前项，验证焦点不会停留在失效节点。
5. 展开/收起分组，验证隐藏项不会继续获得焦点。

### 11.3 下载任务管理器

1. 仅创建一个启动器更新任务，确认“查看日志”可以导航至底部控制。
2. 创建资源下载任务，验证日志、暂停、取消可双向切换。
3. 创建失败任务，验证日志、重试、清除失败任务可双向切换。
4. 打开日志抽屉，验证关闭后回到对应任务日志按钮。
5. 在任务列表持续更新时，连续使用方向键导航，确认不会锁死或跳到背景页面。
6. 在 Steam Deck 键盘模拟布局下，使用社区 MC 常见按键完成上述流程。

## 12. Code Review 检查点

审查焦点相关变更时，优先检查以下风险：

- 新增元素是否缺少 `focusKey`，或使用了数组下标。
- 是否在动态布局中仅依赖几何空间导航。
- `onArrowPress` 是否返回 `false` 来阻止不确定的二次导航。
- 显式序列是否包含实际渲染项，是否错误包含禁用/折叠项。
- 状态变更、失败重试、删除和关闭路径是否调用了正确的焦点恢复逻辑。
- 是否把焦点设置在动画尚未完成或组件尚未挂载的节点。
- 是否测试了仅剩一个操作按钮的边界场景。

发现“方向键无响应”“焦点跳到背景”“焦点停在已删除按钮”“某状态只剩一个按钮”任一现象时，应阻止合并，先补齐显式导航和回归用例。
